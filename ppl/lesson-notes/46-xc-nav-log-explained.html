Lesson 46 — X/C Nav Log Explained

▶ Watch lesson   Back to course

Core idea

  • A VFR navigation log converts a charted route into leg-by-leg expectations for course, heading, distance, groundspeed, time, fuel, altitude, and frequencies.
  • The transcript treats it as a complete planning workflow: draw a sensible route, select useful checkpoints, calculate each leg, then compare actual progress against the plan in flight.

1. Plot a sensible route

  • Start with a direct departure-to-destination line on the sectional, then modify only as needed for airspace, terrain/obstacles, restricted areas/TFRs, weather, suitable checkpoints, or operational considerations.
  • Avoid unnecessary zigzags: every dogleg adds distance, time, fuel, and workload.
  • Check current chart/airport/NOTAM information before treating the drawn route as flyable.

2. Select checkpoints

  • Use distinctive, easily recognized features such as airports, towns, lakes, large highway/railroad intersections, or other prominent landmarks.
  • Space checkpoints so they provide useful position/timing updates without creating constant heads-down work.
  • A checkpoint should answer: “Will I confidently recognize this from my planned altitude and direction?”

3. Distance and true course

  • Measure each leg's distance in nautical miles using the sectional scale or a plotter.
  • Measure true course (TC) against a meridian/longitude line, not the edge of the paper.
  • Record leg and cumulative distance; cumulative values help judge overall progress and remaining fuel/time.

4. Choose altitude

  • Consider terrain/obstacle clearance, airspace, weather/clouds, winds aloft, aircraft performance, radio/navaid coverage, and VFR cruising-altitude rules when applicable.
  • A single cruise altitude may not be best for the entire route if terrain or airspace changes.

5. Forecast wind and true airspeed

  • Enter forecast wind direction/speed for the planned altitude/time. Winds aloft are referenced to true north.
  • Determine planned true airspeed (TAS) from POH cruise data/conditions, not simply indicated airspeed.

6. Wind correction and groundspeed

  • Use an E6B/electronic calculator to solve wind-correction angle (WCA) and groundspeed (GS).
  • Apply WCA to true course to get true heading (TH).
  • Sanity check: a headwind component should reduce GS, a tailwind increase it; a crosswind should require a crab into the wind.

7. True → magnetic → compass heading

  • Apply local magnetic variation from the sectional to convert true heading/course to magnetic values.
  • Apply compass deviation from the aircraft's correction card if the planning form/workflow calls for compass heading.
  • Keep sign conventions consistent. A memorized mnemonic is less important than checking that the result makes geographic sense.

8. Time

  • Time = distance ÷ groundspeed.
  • Convert decimal hours to minutes by ×60; or use E6B scales directly.
  • Record leg ETE and cumulative ETE. Add realistic taxi, run-up, climb, and descent effects rather than assuming cruise from brake release to touchdown.

9. Fuel

  • Fuel used = fuel flow × time.
  • Use POH/actual conservative taxi, climb, cruise, descent, and reserve assumptions. Cruise fuel flow alone understates total trip fuel.
  • Compare planned fuel at checkpoints with actual tank/time indications; unexplained excess burn is a cue to reassess.

10. Frequencies / navaids / notes

  • Preload or write frequencies for departure, destination, CTAF/tower, weather, approach/flight following, and relevant FSS/navaids.
  • Record VOR/GPS checkpoints, runway information, or special airspace notes that reduce cockpit searching.

Top of climb / descent

  • Climb consumes time, distance, and fuel at different speeds/flows than cruise; include it when meaningful.
  • Plan descent early enough to arrive at pattern/terminal altitude without steep, high-workload last-minute descents.
  • Use POH climb/descent performance or conservative real-world values rather than generic numbers.

Inflight use

  • “Hack”/start a clock and record actual takeoff/checkpoint times.
  • At each checkpoint compare actual position/time/heading/fuel with expected values.
  • If timing error grows, check wind/GS. If visual position does not match, solve the position problem early instead of continuing on assumption.
  • The log remains useful even with GPS because it gives independent expectations.

What to remember

  • Route → checkpoints → distance/TC → altitude/wind/TAS → WCA/GS → heading → time → fuel.
  • True course and heading are different once wind correction is applied.
  • GS determines time; time × flow determines fuel.
  • Actual vs planned checkpoint performance is the real value of the nav log.
